# داشبورد Paperclip + Herdr

داشبورد فارسی (`app.py` و `index.html`) یک **کلاینت** برای Paperclip است. سرور اصلی Paperclip و رابط آن روی پورت ۳۱۰۰ و داشبورد به‌طور پیش‌فرض روی پورت ۸۰۰۰ هستند. پایتون ۳.۱۰ یا بالاتر کافی است؛ به Flask، urllib3 یا `pip install` نیازی نیست. **Herdr فقط برای خواندن خروجی ترمینال و استفاده از `bridge.sh` لازم است.**

## اجرای سریع از ریشهٔ مخزن

```bash
# ترمینال اول؛ Node 24 LTS (24.15.0+) یا 26+ و npm 11.16+
npm ci
npm start
```

پس از دریافت `status: "ok"` از `http://localhost:3100/api/health` در رابط Paperclip یک Company بسازید. سپس:

```bash
# ترمینال دوم؛ در لینوکس/مک می‌توانید python3 بنویسید
python dashboard/app.py --open-browser
```

یا در ویندوز فقط `setup-dashboard.cmd` را باز کنید. راه‌انداز سرور آماده را دوباره اجرا نمی‌کند؛ برای شروع یک سرور جدید، از بستهٔ محلی پروژه استفاده می‌کند تا نسخه و اصلاحیه‌های وابستگی‌ها قابل تکرار باشند. اگر نصب محلی آماده نباشد، ابتدا `npm.cmd ci` اجرا می‌شود. مهلت آمادگی پیش‌فرض ۱۸۰ ثانیه است و **بعد از نصب** حساب می‌شود. خطای شروع یا پاسخ نامعتبر API باعث توقف راه‌انداز می‌شود، نه باز شدن یک داشبورد ظاهراً سالم.

اگر روی ویندوز چند `py.exe` یا `python.exe` دارید، لازم نیست آن‌ها را حذف کنید. راه‌انداز مسیرها را تک‌تک امتحان می‌کند: ابتدا `py.exe -3` و سپس `python.exe`. مسیر اولین فرمانی که واقعاً Python 3.10+ اجرا کند با `Using Python command:` نمایش داده می‌شود.

نمونه برای اتصال به **سروری که خودتان روی پورت دیگری بالا آورده‌اید**:

```powershell
.\setup-dashboard.cmd -PaperclipUrl http://localhost:3200 -DashboardPort 8080
```

## تنظیمات `dashboard/.env`

برای اجرای دستی، در صورت نیاز `dashboard/.env.example` را در کنار خودش به نام `.env` کپی کنید. برای حالت پیش‌فرض فایل لازم نیست. راه‌انداز ویندوز اگر فایل وجود نداشته باشد آن را می‌سازد و در اجرای مجدد فقط تنظیماتی را که **صریحاً** به آن داده‌اید به‌روز می‌کند. برای بازگشت از شناسهٔ شرکت قدیمی به انتخاب خودکار، خط `PAPERCLIP_COMPANY_ID` را خالی یا کامنت کنید.

| کلید | کاربرد |
|---|---|
| `PAPERCLIP_API_URL` | آدرس پایهٔ سرور، بدون `/api`؛ پیش‌فرض `http://localhost:3100` |
| `PAPERCLIP_COMPANY_ID` | خالی: تنها شرکت به‌صورت خودکار انتخاب می‌شود. چند شرکت: یک `id` از `/api/companies` را وارد کنید. شرکت یا ایجنت به‌صورت پنهان ساخته نمی‌شود. |
| `PAPERCLIP_API_KEY` | فقط برای دسترسی احراز هویت‌شده: کلید دارای مجوز شرکت و عملیات موردنظر. درخواست از بک‌اند ارسال می‌شود؛ کلید را در HTML یا Git نگذارید. اگر کلید نمی‌تواند فهرست شرکت‌ها را بخواند، شناسهٔ شرکت را نیز صریحاً تنظیم کنید. |
| `DASHBOARD_HOST` / `DASHBOARD_PORT` | پیش‌فرض `127.0.0.1:8000`. داشبورد ورود کاربر ندارد؛ آن را مستقیم در شبکهٔ عمومی منتشر نکنید. اگر در فایل قدیمی مقدار `0.0.0.0` دارید، برای استفادهٔ محلی آن را به `127.0.0.1` تغییر دهید. |
| `HERDR_AGENT_MAP` | نگاشت اختیاری، مثل `Antigravity-Worker=agy-worker,Freebuff-Coder=w2:p1` |

مقدار فعال در **فایل `.env` بر محیط شل مقدم است**؛ فایل با `utf-8-sig` خوانده می‌شود و خطوط کامنت نادیده گرفته می‌شوند. پس از تغییر فایل، داشبورد را دوباره اجرا کنید. `-CompanyId`، `-DashboardHost` و `-DashboardPort` در راه‌انداز ویندوز نیز قابل استفاده‌اند.

## آزمون و عیب‌یابی

```bash
python dashboard/test_connectivity.py        # سرویس واقعی: سلامت سرور، دسترسی شرکت و ایجنت‌ها
python -m unittest discover -s dashboard -v  # آزمون آفلاین؛ بدون npm یا Herdr
```

- `/health` روی پورت داشبورد سلامت Paperclip را **مستقل از تعداد شرکت‌ها و ایجنت‌ها** نشان می‌دهد. اگر سرور آنلاین است ولی شرکتی وجود ندارد، ایجاد اولین شرکت کافی است؛ داشبورد دوباره تلاش می‌کند. خطای دسترسی یا شناسهٔ اشتباه جدا نمایش داده می‌شود.
- برای خواندن خروجی، Herdr باید در `PATH` و با همان کاربر اجرا شده باشد. ابتدا `HERDR_AGENT_MAP` (شناسه یا نام Paperclip)، سپس نام‌های `herdr agent list` و بعد شناسهٔ پنجره بررسی می‌شوند.
- بیدارباش با `POST` ارسال می‌شود. پرامپت دستی هنوز پیاده‌سازی نشده است. نبودن خروجی Herdr به معنی خاموش بودن Paperclip نیست.
