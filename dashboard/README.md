# میز کار دوزبانهٔ Paperclip + Herdr

[معرفی و تصاویر دو زبان](../README.md) · [English setup & troubleshooting](../docs/SETUP.en.md)

داشبورد دوزبانه یک **کلاینت** برای Paperclip است. سرور اصلی Paperclip و رابط آن روی پورت ۳۱۰۰ و داشبورد به‌طور پیش‌فرض روی پورت ۸۰۰۰ هستند. پایتون ۳.۱۰ یا بالاتر کافی است؛ به Flask، urllib3 یا `pip install` نیازی نیست. **برای برنامه‌ریزی و تحویل دستی نیازی به Herdr ندارید؛ برای ارسال خودکار و خواندن خروجی، نشست واقعی Herdr لازم است.**

## اجرای سریع از ریشهٔ مخزن

```bash
# ترمینال اول؛ Node 24 LTS (24.15.0+) یا 26+ و npm 11.16+
npm ci
npm start
```

پس از دریافت `status: "ok"` از `http://localhost:3100/api/health` در رابط Paperclip یک Company بسازید. سپس:

```bash
# ترمینال دوم؛ در لینوکس/مک می‌توانید python3 بنویسید
python dashboard/app.py --open-browser
```

یا در ویندوز فقط `setup-dashboard.cmd` را باز کنید. راه‌انداز سرور آماده را دوباره اجرا نمی‌کند؛ برای شروع یک سرور جدید، از بستهٔ محلی پروژه استفاده می‌کند تا نسخه و اصلاحیه‌های وابستگی‌ها قابل تکرار باشند. اگر نصب محلی آماده نباشد، ابتدا `npm.cmd ci` اجرا می‌شود. مهلت آمادگی پیش‌فرض ۱۸۰ ثانیه است و **بعد از نصب** حساب می‌شود. خطای شروع یا پاسخ نامعتبر API باعث توقف راه‌انداز می‌شود، نه باز شدن یک داشبورد ظاهراً سالم.

**انتخاب پایتون در ویندوز:** به PyManager، `py.exe` یا تغییر `PATH` نیازی نیست. راه‌انداز فایل‌های اجرایی موجود در `PATH`، نصب‌های ثبت‌شده در رجیستری Python و پوشه‌های متداول نصب (از جمله `%LOCALAPPDATA%\Programs\Python` و `%LOCALAPPDATA%\Python`) را بررسی می‌کند. از هر مفسر نسخه و مسیر واقعی `sys.executable` را می‌پرسد و جدیدترین Python 3 سازگار را مستقیم روی `dashboard/app.py` اجرا می‌کند. مثلاً بین ۳.۱۴ و ۳.۱۵، اگر هر دو قابل اجرا باشند، ۳.۱۵ انتخاب می‌شود. خط `Using Python ...:` نسخه و مسیر انتخاب‌شده را نشان می‌دهد.

در صورت نیاز **یکی** از این دو روش را به‌جای انتخاب خودکار استفاده کنید. در روش دوم مسیر نمونه را با مسیر واقعی نصب خودتان عوض کنید:

```powershell
.\setup-dashboard.cmd -PythonVersion 3.14
.\setup-dashboard.cmd -PythonExe "D:\Tools\Python315\python.exe"
```

اگر نسخه یا مسیر درخواستی کار نکند، راه‌انداز خطا می‌دهد؛ بی‌صدا به نسخهٔ دیگری نمی‌رود.

نمونه برای اتصال به **سروری که خودتان روی پورت دیگری بالا آورده‌اید**:

```powershell
.\setup-dashboard.cmd -PaperclipUrl http://localhost:3200 -DashboardPort 8080
```

با دکمه‌های **فارسی / English** زبان و جهت صفحه را بدون بارگذاری مجدد تغییر دهید. این کار فرم، مقادیر انتخابی، درخواستِ ثبتِ در انتظار یا محتوای تیکت را تغییر نمی‌دهد. مرورگر تنها ترجیح زبان را حفظ می‌کند.

## اولین تیم و اولین طرح

1. **شرکت را بررسی کنید.** انتخاب شرکت و فهرست اعضا از API واقعی Paperclip است. خالی بودن Agents یعنی باید عضو بسازید، نه اینکه سرور خاموش است. اگر چند شرکت دارید، یک‌بار `-CompanyId` یا `PAPERCLIP_COMPANY_ID` را مشخص کنید.
2. **یک‌بار عضو ثبت کنید.** در «تیم ایجنت‌ها» Freebuff، Antigravity یا «ایجنت دیگر» را انتخاب کنید، نام بدهید و «ثبت در شرکت» را بزنید. برای **دستی** همین کافی است. برای **متصل**، اول ایجنت را در پوشهٔ پروژه داخل Herdr باز کنید (مثلاً `agy`)، ورودش را کامل کنید و از «یافتن نشست‌ها» هدف واقعی را برگزینید. استفاده از نام پایدار به‌جای شمارهٔ پنجره بهتر است. در یک پنجره هم‌زمان دستور دیگری ندهید. این فرم برنامه‌ای نصب یا اجرا نمی‌کند، `HERDR_AGENT_MAP` هم عضو نمی‌سازد.
3. **در صورت نیاز استخدام را تأیید کنید.** اگر سیاست شرکت تأیید می‌خواهد، لینک «تأیید استخدام» بخش Approvals همان شرکت را باز می‌کند. پس از تأیید چند ثانیه برای آماده‌سازی فرصت دهید. عضو معلق، متوقف یا دارای خطا در گزینه‌های مسئول نمی‌آید. برای ایجنت‌هایی که از قبل در Paperclip ثبت کرده‌اید، تنظیم آداپتور حفظ می‌شود؛ نیازی به استخدام دوباره نیست.
4. **یک کار را تقسیم کنید.** در «میز تقسیم کار» عنوان جدید بنویسید یا تیکتی موجود را برای کار اصلی انتخاب کنید. ۱ تا ۲۰ ردیف با عنوان، شرح اختیاری و ایجنت مسئول بسازید. «الگوی سه‌مرحله‌ای» پیشنهاد ثابت و قابل‌ویرایش است، نه تولید خودکار با مدل. «ثبت طرح» زیرکارهای دارای `parentId` و `assigneeAgentId` را در **Backlog** همان شرکت می‌سازد؛ هیچ پرامپتی نمی‌فرستد. اگر ارتباط وسط ثبت قطع شد، بدون بستن صفحه، **تلاش مجدد همین طرح** را بزنید. دادهٔ فرم در مرورگر ذخیره نمی‌شود؛ بعد از بارگذاری مجدد اول تیکت‌های موجود را ببینید.
5. **فقط کار آماده را شروع کنید.** در «کارهای شرکت» بر اساس مسئول فیلتر کنید. برای متصل، «ارسال به صف اجرا» می‌تواند بلافاصله Paperclip را بیدار کند؛ worker با توکن همان اجرا، یک تیکت را به ایجنت آماده در Herdr تحویل می‌دهد. برای دستی، «شروع دستی» را بزنید و «برگهٔ کار» را در **خودِ Freebuff یا ایجنت، نه پرامپت شل** بچسبانید. پس از پایان کار دستی «آمادهٔ بازبینی» را بزنید. لینک «بازبینی در Paperclip» همان تیکت را باز می‌کند؛ نتیجه را بررسی و در Paperclip تعیین تکلیف کنید. `in_review` به معنی `done` نیست.

**نمونه:** «افزودن جست‌وجوی مشتریان» ← «ساخت فیلتر با آزمون واحد» برای Antigravity؛ «آزمون حالت خالی و گزارش خطا» برای Freebuff. زیرکار دوم را پس از آماده‌شدن اولی آغاز کنید؛ صرفِ شمارهٔ ردیف، وابستگی زمان‌بندی نمی‌سازد.

## تنظیمات `dashboard/.env`

برای اجرای دستی، در صورت نیاز `dashboard/.env.example` را در کنار خودش به نام `.env` کپی کنید. برای حالت پیش‌فرض فایل لازم نیست. راه‌انداز ویندوز اگر فایل وجود نداشته باشد آن را می‌سازد و در اجرای مجدد فقط تنظیماتی را که **صریحاً** به آن داده‌اید به‌روز می‌کند. برای بازگشت از شناسهٔ شرکت قدیمی به انتخاب خودکار، خط `PAPERCLIP_COMPANY_ID` را خالی یا کامنت کنید.

| کلید | کاربرد |
|---|---|
| `PAPERCLIP_API_URL` | آدرس پایهٔ سرور، بدون `/api`؛ پیش‌فرض `http://localhost:3100` |
| `PAPERCLIP_COMPANY_ID` | خالی: تنها شرکت به‌صورت خودکار انتخاب می‌شود. چند شرکت: یک `id` از `/api/companies` را وارد کنید. شرکت یا ایجنت به‌صورت پنهان ساخته نمی‌شود. |
| `PAPERCLIP_API_KEY` | فقط برای دسترسی احراز هویت‌شده: کلید دارای مجوز شرکت و عملیات موردنظر. درخواست از بک‌اند ارسال می‌شود؛ کلید را در HTML یا Git نگذارید. اگر کلید نمی‌تواند فهرست شرکت‌ها را بخواند، شناسهٔ شرکت را نیز صریحاً تنظیم کنید. |
| `DASHBOARD_HOST` / `DASHBOARD_PORT` | پیش‌فرض `127.0.0.1:8000`. داشبورد ورود کاربر ندارد؛ آن را مستقیم در شبکهٔ عمومی منتشر نکنید. اگر در فایل قدیمی مقدار `0.0.0.0` دارید، برای استفادهٔ محلی آن را به `127.0.0.1` تغییر دهید. |
| `HERDR_AGENT_MAP` | فقط نگاشت خواندن خروجی اعضای قدیمی؛ نه ثبت یا مسیر ارسال. مثال: `Antigravity-Worker=agy-worker,Freebuff-Coder=w2:p1` |

مقدار فعال در **فایل `.env` بر محیط شل مقدم است**؛ فایل با `utf-8-sig` خوانده می‌شود و خطوط کامنت نادیده گرفته می‌شوند. پس از تغییر فایل، داشبورد را دوباره اجرا کنید. `-CompanyId`، `-DashboardHost` و `-DashboardPort` در راه‌انداز ویندوز نیز قابل استفاده‌اند.

## آزمون و عیب‌یابی

```bash
python dashboard/test_connectivity.py        # سرویس واقعی: سلامت سرور، دسترسی شرکت و ایجنت‌ها
python -m unittest discover -s dashboard -v  # آزمون آفلاین؛ بدون npm یا Herdr
```

اگر **بعد از** خط `Using Python ...:` پیام `timeout` برای `/api/health` می‌بینید، پایتون پیدا شده است؛ این بار نوبت بررسی **Paperclip** است. راه‌انداز درخواست محلی را بدون پراکسی می‌فرستد و برای سرویسی که روی پورت گوش می‌دهد ولی هنوز پاسخ نداده، تا پایان مهلت دوباره تلاش می‌کند. برای نصب سردِ کند می‌توانید `-StartupTimeout 300` بدهید. خطای HTTP یا پاسخ غیرمنتظره نشانهٔ آمادگی نیست و با اجرای سرور دوم نادیده گرفته نمی‌شود.

```powershell
# در PowerShell، از ریشهٔ مخزن و برای پورت پیش‌فرض:
curl.exe --noproxy "*" --max-time 8 http://127.0.0.1:3100/api/health
Get-NetTCPConnection -State Listen -LocalPort 3100 -ErrorAction SilentlyContinue | Select-Object LocalAddress, OwningProcess
```

- اگر `curl.exe` مقدار `"status":"ok"` برگرداند ولی `localhost` کار نکند، `.\setup-dashboard.cmd -PaperclipUrl http://127.0.0.1:3100` را اجرا کنید.
- اگر پورتی در حال شنیدن نیست و `npm start` هم در حال اجرا نیست، `npm.cmd start` را در ریشهٔ مخزن اجرا کنید تا **اولین خطای سرور** یا آدرس واقعی آن را ببینید. برای بررسی تنظیمات `npm.cmd run doctor` در دسترس است. اگر پورت اشغال است، ابتدا PID و خروجی همان سرویس را بررسی کنید، نه اینکه نمونهٔ دوم را اجرا کنید.
- `/health` روی پورت داشبورد سلامت Paperclip را **مستقل از تعداد شرکت‌ها و ایجنت‌ها** نشان می‌دهد. اگر سرور آنلاین است ولی شرکتی وجود ندارد، ایجاد اولین شرکت کافی است؛ داشبورد دوباره تلاش می‌کند. خطای دسترسی یا شناسهٔ اشتباه جدا نمایش داده می‌شود.
- اگر عضو متصل ظاهر نمی‌شود، `herdr agent list` را با همان کاربر و در همان نشست اجرا کنید. برای تشخیص بیشتر `herdr agent explain <target>` را ببینید. Paperclip، داشبورد، Python و Herdr باید مسیرهای فایل و حساب سیستم‌عامل مشترک داشته باشند؛ Paperclip داخل Docker/WSL و داشبورد ویندوز لزوماً این‌طور نیستند. برای عضو دستی نیازی به اجرای CLI در سرور نیست.
- اگر فهرست شرکت درست است ولی استخدام خطا می‌دهد، مجوز ساخت ایجنت و فعال بودن آداپتور `process` را در Paperclip بررسی کنید. تنظیم آداپتور یک عضو موجود بازنویسی نمی‌شود. جابه‌جایی مخزن یا حذف مفسر Python می‌تواند مسیر worker ثبت‌شده را نامعتبر کند.
- `blocked`، `error`، گم‌شدن ترمینال یا مهلت ۳۰ دقیقه: برگهٔ اجرا و خود نشست را ببینید. اگر پرامپت رسیده ولی ثبت بازبینی شکست خورده، نتیجه را دستی در Paperclip پیگیری کنید؛ آن را دوباره به ایجنت ندهید. میز کار روی شل خالی تایپ نمی‌کند یا درخواست اجازهٔ ایجنت را خودکار تأیید نمی‌کند.
- مدیریت، مشاهدهٔ نشست‌ها و خروجی ترمینال فقط با آدرس محلی و از همین دستگاه مجاز است. نمایش فقط‌خواندنی روی شبکه نیز می‌تواند اطلاعات تیکت‌ها را آشکار کند؛ آن را عمومی نکنید.
